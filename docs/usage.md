# 桌面小伴侣

Waveshare ESP32-S3-RLCD-4.2 固件与 Windows 托盘后台程序，通过 BLE 同步便签和新闻。

## 使用

双击“启动小伴侣.bat”或“后台启动.bat”，程序直接在系统托盘运行，不显示主窗口。右键点击托盘图标，菜单中只有“设置…”和“退出”。重复启动也不会弹窗。

| PC 操作 | 默认快捷键 |
| --- | --- |
| 静默发送当前选中文字 | Ctrl+Alt+J |
| 唤醒输入框 | Ctrl+Alt+空格 |
| 框选截图并识别成便签（验证图片 API 后启用） | Ctrl+Alt+K |
| 为最后一条已送达便签设置提醒 | Ctrl+Alt+L |
| 发送输入框内容并收起 | Enter |
| 输入框内换行 | Shift+Enter |
| 收起输入框 | Esc |

Ctrl+Alt+J 不弹出窗口或通知。Ctrl+Alt+空格只在托盘附近弹出小输入框，支持文字、粘贴和 Windows 语音输入；回车发送后立即收起，点击别处或按 Esc 也会收起。中文输入法选词时，回车先确认候选文字。

划选发送使用独立取词进程及 Win32 剪贴板接口，不再在托盘进程中持有或恢复 OLE 剪贴板对象。取词超时或底层异常只使本次取词失败，托盘、BLE 和其他功能继续运行；错误只记录在本地日志及托盘提示中。取词后尽力恢复原剪贴板中的文字、HTML、RTF、DIB/PNG 等常见格式，若用户或其他程序已经复制了更新的内容，则保留更新内容。

小输入框中的“语音”调用 Windows 语音输入（Win+H），需要麦克风和网络。右键托盘图标进入“设置”，可修改快捷键、便签上限、GDELT 查询、新闻代理和设备地址（留空自动发现）。状态与错误只保留在托盘悬停提示及本地日志中；输入错误仅在已打开的小输入框内显示。

| 小屏幕操作 | 功能 |
| --- | --- |
| 双击 KEY | 切换便签 / 新闻 |
| 两种模式短按 BOOT / KEY | 下一条 / 上一条；长内容先翻内容页 |
| 两种模式长按 BOOT | 删除当前便签 / 新闻 |
| 两种模式长按 KEY | 置顶 / 取消置顶当前便签 / 新闻 |
| 便签模式双击 BOOT | 在 PC 托盘附近显示当前便签，可复制文字、按 Esc 关闭 |
| 新闻模式双击 BOOT | 在 PC 默认浏览器打开当前新闻 |
| 长按 PWR / 短按 PWR | 关机 / 开机 |

PWR 只连接硬件电源电路，模式切换采用“双击 KEY”。两枚按键的单击均等待约 350 毫秒判定，双击不会额外触发翻页；长按约 1 秒触发一次。

便签上限可设置为 1–20 条，默认 20 条；保存后通过 BLE 同步到设备并持久保存。降低上限不会删除已有便签：上限低于当前便签数或待发送条数时会拒绝保存。

每条最多 3072 UTF-8 字节（约 1024 个汉字）。置顶便签排列在前；满额时替换最早的未置顶便签；全部置顶时保留已排队的待发送内容。设备 Flash 保存便签和新闻缓存，PC 保存已确认便签的备份以及离线发送队列。

## 小屏幕显示设置

右键托盘 → 设置 → 显示，可设置：

- 显示风格：白底黑字或黑底白字。
- 字体大小：12、16、24、32 像素；24/32 使用中文位图字形放大，顶部状态栏字号保持不变。
- 行间距：0–16 像素，表示文字行之间额外增加的距离，默认 7 像素。
- 是否显示底部操作提示。关闭后正文使用腾出的阅读空间，按键功能保持不变；短暂的操作结果提示仍可出现。

设置经 BLE 同步并保存在设备 Flash 中，断开 PC 或重启后仍然有效。便签和新闻会根据字号、行距与可用高度重新分页，所有内容仍可通过 BOOT / KEY 翻页查看。

顶部状态栏显示当前模式、日期时间（年-月-日 时:分）、蓝牙图标和电池图标。蓝牙断开时图标带斜线；不再显示连接状态文字或电量百分比。电池填充量按[微雪官方 ADC 示例](https://docs.waveshare.com/ESP32-S3-RLCD-4.2/ESP-IDF#03_adc_test)读取 ADC1 通道 3，并根据[板卡原理图](https://files.waveshare.com/wiki/ESP32-S3-RLCD-4.2/ESP32-S3-RLCD-4.2-schematic.pdf)换算电压，校准、采样滤波后每 5 秒更新。它是电压估算的电量指示。

PC 在每次 BLE 连接成功时校时，连接期间约每 4 小时再同步一次；失败后稍后重试。屏幕按北京时间显示，并在每分钟更新。设备将时间写入板载 PCF85063A RTC，重启后直接恢复时间；PC 关闭或蓝牙断开后仍继续走时。

## HN + GDELT 混合新闻

- 来源包括 Hacker News API 和 GDELT DOC 2.0；共用默认 20 条的列表，可在“设置 → 新闻”中调整为 1–50 条。
- 每个来源各自每 600 秒刷新。以程序启动时间为基准，HN 在 0、10、20 分钟启动，GDELT 在 5、15、25 分钟启动。使用单调时钟调度，正常请求耗时不会逐轮推迟刷新。
- 两个来源各自按时间排序后交替混排，默认通常各占 10 条。来源不足时由另一来源补足；同一文章的 URL 会去重。
- 阅读、翻页和在 PC 打开网页都不会删除新闻。置顶条目排在前面并在刷新时保留，其余位置用较新的新闻替换较早的普通新闻。上限低于已置顶数量时拒绝保存。
- 长按 BOOT 删除的新闻会留下删除记录，后续刷新、断线重连不会重新加入；设备端记录最近 256 个删除 ID，PC 端持续保存删除 ID 和文章 URL 摘要。
- 小屏幕在每条新闻的序号旁显示 [HN] 或 [GDELT]。GDELT 条目显示媒体域名，不显示 HN 分数或评论数。
- 一个来源失败不会清空另一个来源或其自身缓存。GDELT 返回 HTTP 429 时不会立即重试，并尊重服务端的等待时间；暂停、断网或限流后，实际刷新可能晚于计划。
- GDELT 默认查询 sourcelang:english，获取最近一天的英文综合新闻，按时间倒序。可在“设置 → GDELT 查询”修改，例如 sourcelang:chinese 或 ("artificial intelligence" OR technology)。保存后在下一次 GDELT 刷新生效。
- 启动时先显示缓存；首次安装没有 GDELT 缓存时，其新闻在首个 GDELT 刷新时加入。

官方接口资料：[Hacker News API](https://github.com/HackerNews/API)、[GDELT DOC 2.0](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/)。

## 中文新闻简讯

右键托盘图标 → 设置 → 大模型，填写 API 基础地址、模型名称、API 密钥，勾选“启用中文新闻简讯”后保存。地址通常类似 https://供应商域名/v1，也可以填写完整的 /chat/completions 地址。本地模型支持 http://localhost。采用 [Chat Completions 接口格式](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

PC 会读取新闻正文并在需要时检索相关报道，调用所填 API 生成 60–120 个汉字的简体中文简讯，校验长度后再通过 BLE 发送；小屏幕保留 [HN] / [GDELT] 来源标记。只整理已确认的新闻事实，不加入资料获取情况的解释。已生成的简讯会缓存，重复刷新同一新闻不会反复调用模型。

API 失败或返回长度不合格时保留上次设备缓存，稍后重试，不把未通过校验的模型内容发到设备。新闻抓取和模型生成由独立线程处理，仍保持两个新闻源的错峰调度。未配置 API 时可以继续使用原始标题模式。

API 密钥使用 Windows DPAPI 加密，保存在 data/news-api-key.dpapi；不写入 state.json、日志或设备。设置中的密钥输入框始终隐藏文字，留空保存会保持原密钥。新闻功能只发送新闻资料；截图和提醒功能分别发送所选图片与用于设置提醒的便签。

## 截图识别与提醒

在“设置 → 大模型”点击“验证 API 与图片能力”，程序先验证文字接口，再发送一张本机合成的数字测试图。通过真实识别后才能在“工具”中启用截图快捷键；API 地址、模型或密钥改变后须重新验证。图片采用 [Chat Completions 图片输入格式](https://developers.openai.com/api/docs/guides/images-vision?api-mode=chat)。

Ctrl+Alt+K 后拖动框选区域，Esc 取消。只把所选区域上传到配置的 API；完整桌面只暂存内存，不写入文件、不上传。模型先识别场景：文章、文档、通知、清单等纯文本图片逐字完整保留所有可辨认文字，不摘要、不改写、不翻译，保留原始语言、数字、标点、换行、编号和缩进；微信等聊天或交互界面则按上下文整理事项与结论，理解人物归属、否定、取消、改期等信息，去除无关界面和寒暄。简单表格保留表头和行列对应，以每行一条、竖线分列的纯文本显示；过宽的表格按记录改为“字段：值”。识别结果自动进入便签发送队列，换行与分项保留并在设备上分页。超过单条便签 3072 UTF-8 字节时提示缩小选区，不静默删字或截断。

Ctrl+Alt+L 读取最后一条已成功送达的便签，通过 AI 识别提醒时间；提醒便签正文会发送到所配置的 API。PC 弹出确认框，可修改时间后点击“确认提醒”。没有明确时间或时间已过时不擅自添加默认时间，由用户自行填写。取消不会创建提醒。

提醒保存在 data/reminders.json。设置时，提醒时间相同（精确到分钟）的多条便签自动合为一组，确认框会提示已有几条便签。同一便签不会在组内重复。

已确认的提醒经 BLE 保存到设备 Flash，由设备时钟独立触发，设备持续供电时，断开蓝牙或关闭 PC 后仍可提醒。到点自动切换到便签模式并定位对应便签，屏幕缓慢反色闪烁约 7 秒，然后保持提醒画面一分钟；合并组每 5 秒轮流显示一条，较大的组会延长到至少轮换一遍。按 BOOT 或 KEY 关闭提醒，便签仍保留。在线 PC 同时显示一次合并便签和系统通知；重连不会再次触发已完成的设备提醒。

设备保存最早的 64 组待提醒日程；超过部分或已不在设备中的便签由运行中的 PC 提醒。PC 休眠期间未触发的 PC 提醒会在恢复后补发。提醒时间按北京时间处理。

新闻接口、正文与相关报道检索共用“设置 → 新闻”的代理策略：自动（系统/直连）、自定义 HTTP/HTTPS 代理或不使用代理。自定义示例 http://127.0.0.1:7897，只接受代理软件的 HTTP/混合端口，不接受 SOCKS 或含账号密码的地址。自定义代理失败时不尝试直连；大模型 API 连接仍使用自身现有方式。保存修改会重新调度新闻更新，已有简讯继续使用缓存。资料较少时再搜索相关公开报道并提取内容。简讯仅输出新闻事实，不解释正文是否获取或材料是否完整。网页不可访问时仍可能只能依据已获得的信息整理，不编造细节。
